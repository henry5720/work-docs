# **2\. 系統概述**

## **專案背景**

於 TeamSync 平台新增「庫存模組」，與核心功能「AI 聊天室」分工：異動可由聊天室或模組發起，模組作為集中檢視品項、倉庫、供應商、各類異動、供需與 AI 分析的入口。主檔以「品項」統稱所有儲存物，以「可作為原料 / 可作為成品」兩旗標區分角色，並以配方（BOM）將原料或其他品項組合為成品。

## **使用者情境（User Story）**

> * 作為倉管人員，我希望以一句話或表單（含單位、異動日期）完成進 / 出 / 調 / 退 / 生，未來日期即為預約、當日或過去即為即時或補登。

> * 作為庫存管理者，我希望於首頁一眼掌握待處理風險、待入 / 待出量與待確認，並由 AI 洞察與供需預測提前處理缺貨、過量、滯銷。

> * 作為管理者，我希望以能力為單位，將檢視、編輯各主檔、聊天室綁定等權限指派給部門或個別使用者。

## **設計原則**

> * 職責分工：異動之「開單」可於 AI 聊天室或庫存模組（異動紀錄）雙入口發起，兩入口共用同一套驗證與落帳程式；既有預約單之「確認 / 取消」亦可於兩處執行。主檔與設定於模組維護。

> * 流水帳模型：所有異動為不可變紀錄；當前庫存由紀錄加總計算，天然保有稽核軌跡。

> * 以最小單位記帳：每筆流水帳一律以品項最小單位（base）儲存，其他單位僅供輸入與顯示。

> * 三桶庫存：可用（能被新動作動用）、待入（未確認之入庫，尚未進倉）、待出（已開單未確認之出庫，實體仍在倉但被鎖）。待入 / 待出以同一「不可用庫存」結構儲存、以類型區分，於庫存列表以「異動中」欄位呈現。

> * 異動日期即模式：異動日期為未來（明日起）＝預約，需人工確認；為今日（含）以前＝即時 / 補登，建立即落帳。損耗與盤點調整不適用預約（詳 5.2）。

> * 電子確認與差異強制手動：入庫類收貨確認須比對單據，差異須於確認步驟內強制手動補記（損耗或盤點；溢收僅能盤點盤盈），原子完成、不留幻影庫存。

> * 權限為能力模型：以可勾選能力授權，可指派給部門或個別使用者；權限與聊天室綁定分屬不同設定。

## **範圍邊界（Out of Scope）**

> * 不含嚴格調撥審批；本期僅自動調撥。不做跨品項單位換算。

> * 配方採單階：含半成品或其他成品時，直接扣該品項庫存、不逐層展開。

> * 供需預測僅依已知事件（現有可用、待入、待出 / 生產排程）推估，不含歷史消耗速度外推。

> * 無退回供應商流程；不建立客戶主檔；不含金流與財務（以外部系統整合）。

> * 存貨計價與單位成本、批號 / 效期追蹤、盤點批次作業等未列本期範圍，已知擴充項目與其觸發時機詳見附錄 B。

## **權限（能力）模型**

權限以能力為單位授予，可指派給部門或個別使用者；有效能力為部門能力與個人能力之聯集。能力清單：檢視權、編輯品項主檔、編輯倉庫主檔、編輯供應商主檔、設定聊天室綁定、設定權限（最高權限，僅管理員）。於模組開單或確認 / 取消預約單另需具該倉之操作權（即該倉所綁定聊天室之成員）。

## **角色定義補充**

> * **最高權限帳號：**持「設定權限」者，於設定 · 權限指派能力。

> * **具設定權之使用者：**持編輯品項 / 倉庫 / 供應商主檔或設定聊天室綁定其中一項或多項者。

> * **一般使用者：**持檢視權者，唯讀查看前三頁；可見範圍依所屬聊天室綁定動態決定（S04）。

> * **聊天室成員：**於聊天室端開單與確認；可操作倉庫由所屬聊天室綁定推導；亦可於模組對其可操作倉開單、確認 / 取消。

## **自定義欄位與欄位顯示規則**

系統三處皆提及「欄位」設定，但性質不同，規則亦不同，須分別對待：

> * **主檔（品項 / 倉庫 / 供應商）自訂欄位：**為「資料源頭」，可建立全新欄位（定義名稱與型別），資料實際儲存於主檔。

> * **庫存列表「欄位顯示挑選」：**非新增欄位，而是「從品項主檔既有欄位中挑選要顯示哪些」。庫存列表為主檔之投影，不產生主檔沒有的新資料。若所挑選之主檔欄位日後被停用 / 刪除，庫存列表之顯示設定須連動移除或標示失效。

> * **異動紀錄自訂欄位：**依「單據類型」設定，非每筆單自由新增；同一類型（如所有進貨單）共用同一組自訂欄位，以維持同類單據資料結構一致、可彙整查詢。不同類型（進 / 出 / 調 / 退 / 損 / 盤 / 生）各自設定。

# **5\. 使用者操作流程**

## **5.1 總流程**

> * 初始設定：指派能力（S01）➔ 建立供應商 / 品項 / 倉庫主檔、定義配方（D01～D04）➔ 倉庫綁定聊天室（S02）➔ 設定聊天室任務（S03）。

> * 日常使用：以雙入口開單執行各異動（T01～T07），於模組三檢視頁查看與確認既有預約單。

## **5.2 異動日期與三種模式**

所有異動單於共用欄位填「異動日期」，系統據此判斷模式：

> * 異動日期為今日（含）以前 → 即時 / 補登：建立即確認、直接落帳，完成時間＝建檔當下，不進待入 / 待出。

> * 異動日期為明日（含）起 → 預約：開單後入庫類記待入、出庫類記待出，須操作者於實際執行時人工確認方落帳；日期到僅提醒、不自動確認。

> * 例外：損耗（T05）與盤點調整（T06）不適用預約，僅可填今日（含）以前之異動日期。盤點差額須實際清點後方能得知、無法預先開單，且盤點之基準為現有在倉（可用＋待出），若其自身亦可產生待出將形成自我參照；損耗則為已發生之事實，非計畫性動作。系統於此二類遇未來日期應阻擋並提示。

> * 由差異流程（收貨、生產確認）強制手動補記之損耗 / 盤點，恆為即時：於該確認步驟原子寫入，不受母單原為預約或即時之影響。

> * 餘額一律以完成時間為準（補登即時生效、不回溯歷史庫存）；異動日期供標記與稽核。統計『今日異動量』依完成時間，『某日實際發生』依異動日期。

## **5.3 庫存異動共用流程（雙入口開單）**

> * 開單入口二擇一：於 AI 聊天室輸入指令（品項、數量、單位、倉別、異動日期）或上傳單據 / 影像；或於庫存模組異動紀錄以表單新增異動單填入相同欄位。

> * 聊天室由 AI 解析並覆述（顯示換算後最小單位與模式判斷）；模組表單則即時驗證欄位並於送出前顯示同等之覆述摘要。兩者未帶單位或日期不明時皆須補齊。

> * 即時 / 補登：確認即落帳。預約：確認即建立預約單並掛待入 / 待出，實際執行時再確認。

> * 入庫類收貨確認比對單據；差異須於確認步驟強制手動補記（短少可選損耗或盤點盤虧、溢收僅能盤點盤盈），原子完成方能結案。

> * 既有預約單之確認 / 取消可於聊天室或模組異動紀錄執行；取消預約須將待出退回可用、待入清除。

## **5.4 調撥流程（T03）**

> * 具 A、B 兩倉操作權者發起；建立時 A 可用 −數量並記入 A 端待出、B 端記待入（一單同時產生待出與待入兩筆）。

> * 貨抵 B，具 B 倉操作權者（聊天室或模組）確認收貨並填實收；落帳：A 待出結清、B 待入 −、B 可用 \+。

> * 實收有落差時強制手動補記（短少損耗或盤點盤虧、溢收盤點盤盈）；差額預設記於收貨端（B），若查明 A 未發出再由管理者調整回 A。

> * 整筆取消時 A 待出退回 A 可用；待入 / 待出未結清者逾時提醒、不得關單。

## **5.5 出貨與生產流程（T02、T07）**

> * 即時 / 補登：出貨確認即扣可用；生產確認即原子扣料、產出成品入可用。

> * 預約（未來異動日期）：出貨開單即將數量自可用移入待出；生產開單即將所需投入品項自可用移入待出（產出之成品不預先佔位）。

> * 實際執行時確認：出貨待出結清、正式出庫；生產待出結清、扣料並將成品計入可用。

> * 生產確認時可回報實際耗料與產出；與配方展開量有差異者強制手動補記（損耗或盤點）。投入品項不足即阻擋、不得部分執行。

## **5.6 退貨流程（T04）**

> * 退貨為待入類，收貨確認時依品況登錄。

> * 良品計入退入倉可用；壞品強制手動記損耗（原因＝退貨壞品 / 報廢），未補記前不得結案；本期無退回供應商。

## **5.7 庫存檢視流程（V01～V03）**

進入模組預設停首頁（AI 總覽）看五格 KPI、AI 洞察與供需預測 ➔ 切庫存總覽看現有庫存 / 可用數 / 異動中大表，點擊某品項×倉庫於側欄鑽取最近 10 筆相關異動、可導向異動紀錄 ➔ 切異動紀錄依類型查詢，並可以表單新增異動單或對既有預約單確認 / 取消。

# **6\. 功能詳述與驗收標準**

## **S01 \- 權限指派（能力模型）**

**目標結果：**於設定 · 權限，將各項能力指派給部門或個別使用者。

**功能規則：**

> * 能力：檢視權、編輯品項 / 倉庫 / 供應商主檔、設定聊天室綁定、設定權限。

> * 每項能力可指派給部門或個人；有效能力為兩者聯集。

> * 「設定權限」為最高權限、僅管理員；此能力可再授予能力，須嚴格控管以防提權。

> * 於模組開單或確認 / 取消預約單另需具該倉操作權；新增 / 移除能力即時生效。

**驗收標準（AC \- 能力指派）：**

**Given** 欲讓採購部可檢視、王小明可編輯品項主檔。

**When** 於設定 · 權限分別指派。

**Then** 採購部可檢視、王小明可編輯品項，其餘不具。

## **S02 \- 聊天室綁定**

**目標結果：**於設定 · 聊天室綁定，以倉庫為單位授予聊天室可視與操作權；與權限分立。

**功能規則：**

> * 以倉庫為單位，可綁一或多個聊天室；可視與操作一併授予。

> * 調撥發起要求同時具 A、B 兩倉操作權。

**驗收標準（AC \- 倉庫授權）：**

**Given** 將 A 倉綁定至採購一室。

**When** 採購一室成員發起 A 倉異動。

**Then** 該成員可操作 A 倉異動。

## **S03 \- 聊天室任務設定與資料庫連接**

**目標結果：**於聊天室設任務為「新庫存管理」並連接庫存資料庫。

**功能規則：**

> * 設定後方可於該聊天室發起庫存異動。

> * AI 人設可於此設定自動調撥規則（A03）。

**驗收標準（AC \- 任務連接）：**

**Given** 聊天室未設定任務。

**When** 成員輸入異動指令。

**Then** 系統不執行並提示需先設定任務。

## **S04 \- 依聊天室動態顯示可操作範圍**

**目標結果：**進入模組時依所屬聊天室僅顯示可檢視 / 可操作之倉庫與品項。

**功能規則：**

> * 確認使用者所屬聊天室（可能複數）。

> * 範圍為各聊天室綁定倉庫之聯集；未涵蓋者不顯示。

**驗收標準（AC \- 範圍顯示）：**

**Given** 使用者屬綁定 A、B 倉之兩聊天室。

**When** 進入模組。

**Then** 僅顯示 A、B 倉及其品項。

## **D01 \- 品項主檔（含單位換算與滯銷天數）**

**目標結果：**以表單建立 / 匯入 / 編輯品項主檔；原料與成品共用同一張主檔。

**功能規則：**

> * 必要欄位：品項名稱、編號、啟用狀態、最小儲存單位、低庫存警示值、過量庫存警示值、滯銷天數。

> * 滯銷天數：每品項可各自設定；超過該天數無出庫類異動（出貨、被生產耗用）即判為滯銷；滯銷與低庫存、過量同屬待處理風險。

> * 類型旗標：可作為原料 / 可作為成品，兩者為獨立旗標、可同時成立。同時成立表示該品項既可作為投入、也可作為產出，涵蓋半成品與「可單獨販售且可作為其他成品組件」之品項（如禮盒內之單品）。

> * 可換算單位：可自建單位並設與最小單位之換算（如 1 盒 \= 10 個），換算率須為整數倍、一經使用即鎖定；流水帳一律以最小單位記帳。

> * 警示值以最小單位計；品項編號唯一；已有交易之品項最小單位不可變更。

> * 停用品項不可被新異動選用；有庫存或未結交易者不可刪除，僅可停用。

**驗收標準（AC \- 滯銷判定）：**

**Given** 某品項滯銷天數設 90，且逾 90 天無出庫。

**When** 系統每小時彙整風險。

**Then** 該品項列入滯銷、納入待處理風險與 AI 洞察。

**驗收標準（AC \- 單位換算）：**

**Given** 精華液最小單位為個、設 1 盒 \= 10 個。

**When** 以「盒」進貨 5 盒並確認。

**Then** 以最小單位記 50 個，覆述顯示「5 盒（=50 個）」。

## **D02 \- 倉庫主檔**

**目標結果：**以表單建立 / 匯入 / 編輯倉庫主檔。

**功能規則：**

> * 必要欄位：倉庫名稱、可存入品項；建議欄位：狀態。

> * 有庫存或未結交易之倉庫不可刪除，僅可停用。

**驗收標準（AC \- 可存入限制）：**

**Given** A 倉僅可存入 X、Y。

**When** 對 A 倉進貨 Z。

**Then** 系統阻擋並提示不可存入。

## **D03 \- BOM 表一覽（配方）**

**目標結果：**獨立主檔頁，定義成品由哪些品項組成。

**功能規則：**

> * 單頭記成品與每次產出量；明細逐列記投入品項與用量（自帶單位）。

> * 投入品項須為「可作為原料」之品項。此旗標與「可作為成品」相互獨立，故投入可為純原料、半成品，亦可為「本身即為成品、同時作為其他成品組件」之品項（組合 / 套組情境，如禮盒內含可單賣之單品）——只需將該品項之「可作為原料」一併勾選即可，無須另建品項。

> * 本期採單階：投入若本身另有配方，生產時直接扣該品項之庫存，不逐層展開為其原料。

> * 禁止循環參照（如 A 之配方含 B、B 之配方又含 A）；組合 / 套組情境下互為投入之機率較高，建立與編輯時皆須偵測並阻擋。

> * 配方變更不溯及既有生產單（生產單以快照為準）。

**驗收標準（AC \- 組合商品）：**

**Given** 單片面膜為可單賣之成品，禮盒需以其為組件。

**When** 將單片面膜之「可作為原料」一併勾選，並加入禮盒配方明細。

**Then** 系統接受該配方；生產禮盒時直接扣單片面膜之庫存。

**驗收標準（AC \- 循環參照）：**

**Given** 品項 B 之配方已含品項 A。

**When** 編輯 A 之配方並加入 B。

**Then** 系統偵測循環參照並阻擋儲存。

## **D04 \- 供應商主檔**

**目標結果：**以表單建立 / 匯入 / 編輯進貨來源之供應商。

**功能規則：**

> * 必要欄位：名稱、編號、狀態；進貨來源以 FK 指向本主檔。

> * 有進貨紀錄者不可刪除、僅可停用；本期無退回供應商流程。

**驗收標準（AC \- 來源綁定）：**

**Given** 已建立供應商甲公司。

**When** 進貨選來源甲公司。

**Then** 進貨以 FK 關聯甲公司。

## **V01 \- 庫存總覽（庫存列表）**

**目標結果：**可見倉庫 × 品項大表；數量由流水帳以最小單位計算，唯讀。

**功能規則：**

> * 顯示每一（倉庫，品項）之現有庫存、可用數與「異動中」；範圍依所屬聊天室。

> * 「異動中」為不可用庫存之呈現欄位，含兩個方向：待入以正數表示（未確認之入庫：進貨 / 調入 / 退貨，貨尚未進倉、不計入現有庫存）、待出以負數表示（已開單未確認之出庫：出貨 / 調出 / 生產投入，實體仍在倉但已被鎖定）。

> * 同一（倉庫，品項）可同時存在待入與待出，此時兩者須並列顯示，不得相互抵銷為單一淨值；否則調撥（A 端待出、B 端待入）等情境將於彙總後歸零而於畫面上消失。

> * 各倉庫欄位個別顯示該倉之待入或待出；僅有單一方向時只顯示該方向。

> * 現有在倉（現有庫存）＝可用＋待出；待入不計入現有庫存。當前可用數＝已確認之進貨＋調入＋良品退貨＋生產產出 − 出貨 − 調出 − 生產投入 − 損耗 ± 盤點調整 − 待出（未確認鎖定）。

> * 出貨 / 生產 / 調出發起時之庫存足量檢查，一律以『可用數』為準（不含待出、待入）。

> * 點擊某（品項×倉庫）之數量，側欄鑽取該品項在該倉最近 10 筆『相關』異動（含被生產消耗、被調撥移動，非整張單），每列顯示時間、類型、增減（含正負與單位）、操作者 / 來源；底部『查看全部』導向 V02 並帶入同一篩選。

> * 欄位顯示挑選：可從品項主檔既有欄位中挑選要於本頁顯示哪些（非新增欄位）；所挑選之主檔欄位若被停用 / 刪除，顯示設定連動移除或標示失效。

**驗收標準（AC \- 雙向並列）：**

**Given** 總部倉某品項有一張進貨待入 100、另有一張出貨預約待出 50。

**When** 檢視庫存列表。

**Then** 異動中欄位並列顯示 \+100 待入與 −50 待出，不顯示淨值 \+50。

**驗收標準（AC \- 調撥不歸零）：**

**Given** 總部倉調撥 30 至北部倉，尚未收貨確認。

**When** 檢視該品項。

**Then** 總部倉顯示 −30 待出、北部倉顯示 \+30 待入；彙總不得相互抵銷為 0。

**驗收標準（AC \- 點擊鑽取）：**

**Given** 總覽顯示品項 X 於 A 倉數量。

**When** 點擊該數量。

**Then** 側欄顯示 X 在 A 倉最近 10 筆相關異動，可導向 V02。

## **V02 \- 異動紀錄（異動紀錄頁）**

**目標結果：**全類型異動查詢與追溯；可以表單新增異動單，並對既有預約單確認 / 取消。

**功能規則：**

> * 類型篩選：全部 / 進貨 / 出貨 / 調撥 / 退貨 / 損耗 / 盤點調整 / 生產。

> * 可依倉庫、品項、時間區間、確認狀態篩選；每筆顯示異動日期、新增 / 完成時間、操作者、確認者、來源。

> * 以完成時間為空作為『未確認（待入 / 待出）』篩選；生產以單頭一列顯示、可展開投入產出。

> * 新增異動單（雙入口之一）：可於本頁以表單開立各類異動單，與 AI 聊天室共用同一套欄位驗證、單位換算、異動日期模式、覆述摘要與差異強制手動規則，並呼叫同一落帳程式；開單需具該倉操作權。

> * 可對既有預約單確認 / 取消（需該倉操作權），確認走同一落帳程式、差異同樣強制手動補記。

> * 由差異流程補記之損耗 / 盤點應標示來源與所屬單號，並可依『差異流程』來源篩選，供事後複核（如調撥短收之責任歸屬待查明者）。

> * 自訂欄位依『單據類型』設定：同一類型共用同一組自訂欄位，不同類型各自設定；非每筆單自由新增。

**驗收標準（AC \- 模組開單）：**

**Given** 倉管人員偏好表單、欲於模組建立一筆盤點調整。

**When** 於異動紀錄新增盤點調整單、填欄位並送出覆述確認。

**Then** 系統以與聊天室相同之規則與落帳程式建立該筆調整。

**驗收標準（AC \- 模組內確認）：**

**Given** 存在一張待完工之生產預約單。

**When** 具該倉操作權者於異動紀錄點『確認完工』。

**Then** 系統原子扣料產出、待出結清，效果與於聊天室確認相同。

**驗收標準（AC \- 取消預約）：**

**Given** 一張明日出貨之預約單掛待出 20。

**When** 操作者取消該單。

**Then** 待出 −20、可用 \+20 退回。

## **V03 \- 首頁儀表板（AI 總覽）**

**目標結果：**模組首頁；彙整庫存與風險，提供 KPI、AI 洞察、供需預測、健康概況與排行；唯讀，資料每小時更新。

**功能規則：**

> * 五格 KPI（皆可點擊下鑽）：待處理風險、今日異動量、待入總量、待出總量、待確認。

> * 待處理風險＝庫存異常（缺貨、低庫存、過量、滯銷）＋逾期未確認之總待辦數；缺貨＝可用 ≤ 0、低庫存＝可用 \< 低庫存警示、過量＝可用 \> 過量警示、滯銷＝逾滯銷天數無出庫。

> * 今日異動量＝今日（以完成時間計）實際落帳之異動筆數（含補登，不含尚未確認之預約）。

> * 待入總量 / 待出總量＝所有未確認入庫 / 出庫鎖定之合計量；格內小字標『其中 X 已逾期』以別於風險格。

> * 待確認＝卡在已開單未確認（待入 / 待出 / 待完工）之異動筆數。

> * AI 風險洞察：列庫存異常（低庫存 / 過量 / 滯銷）與逾期未確認品項 / 單，提供可操作按鈕——『建立調撥』『建議轉店』導向開單流程；『確認完工 / 確認收貨』直接確認既有預約單。

> * 未來 7 日供需預測：依現有可用 \+ 待入 − 待出 / 生產排程推估 7 日內是否破安全庫存；僅計已知事件、不含歷史消耗外推。

> * 庫存健康概況：以（商品×倉組合）狀態長條顯示正常 / 低庫存 / 缺貨 / 異動逾期（＝逾期未確認之待入 / 待出）數；口徑為狀態數，與待處理風險之『事件數』不同、UI 分別標明。

> * 銷貨出庫排行：近 30 天已完成出貨之出庫量排序。

**驗收標準（AC \- 風險彙整）：**

**Given** 目前有低庫存 6、過量 2、滯銷 3、逾期未確認 7。

**When** 開啟首頁。

**Then** 待處理風險顯示 18，並於 AI 洞察列出可點擊處理之品項 / 單。

**驗收標準（AC \- 供需預測）：**

**Given** 某品項現有可用不足、且 7 日內有已排程之生產耗用。

**When** 系統推估。

**Then** 預測列出『將低於安全庫存、預估缺口 N』，並提供調撥按鈕。

## **T01 \- 進貨（待入，兩段式收貨確認）**

**目標結果：**記錄由供應商至指定倉之入庫。

**功能規則：**

> * 專屬：目標倉、供應商（FK）、品項、數量、單位、異動日期。

> * 預約（未來日期）：建立進貨單並記待入（不扣可用），到貨時收貨確認；即時 / 補登（今日含以前）：建立即完成、直接入可用。

> * 收貨確認比對單據：不符時擋住並要求同步強制手動補記——短少可選損耗或盤點盤虧、溢收僅能盤點盤盈；補記允許收貨確認者當下記錄（標記來源、供複核）。

> * 以最小單位落帳；目標倉須允許存入該品項。

**驗收標準（AC \- 進貨短收）：**

**Given** 進貨單 100、實收 96。

**When** 收貨確認填 96、將差額 4 記為損耗。

**Then** 目標倉可用 \+100、損耗 −4，淨額 96；未補記前不得結案。

## **T02 \- 出貨**

**目標結果：**記錄由指定倉至某去向之出庫。

**功能規則：**

> * 專屬：來源倉、去向、品項、數量、單位、異動日期。

> * 預約：開單即將數量自可用移入待出，實際出貨確認才正式出庫、待出結清；即時 / 補登：確認即扣可用。

> * 不可超過來源倉『可用數』（不含待出、待入）。

**驗收標準（AC \- 預約出貨）：**

**Given** A 倉可用 50，開明日出貨 20 之預約單。

**When** 建立預約單。

**Then** 可用 −20 移入待出；實際出貨確認後待出結清、正式出庫。

## **T03 \- 調撥（A 端待出、B 端待入）**

**目標結果：**記錄 A 倉至 B 倉之移撥。

**功能規則：**

> * 專屬：來源倉 A、目標倉 B、品項、數量、單位、異動日期。發起者須同時具 A、B 操作權。

> * 建立時 A 可用 −數量並記 A 端待出、B 端記待入（一單兩筆）；收貨確認須具 B 倉操作權，同一單號冪等。

> * 落帳：A 待出結清、B 待入 −、B 可用 \+；實收落差強制手動補記（短少損耗 / 盤點盤虧、溢收盤點盤盈），差額預設記 B、查明 A 未發再調回 A。

> * 整筆取消時 A 待出退回 A 可用；未結清者逾時提醒、不得關單。

**驗收標準（AC \- 收貨差異）：**

**Given** A 調撥 50 至 B，B 實收 45。

**When** B 確認 45、差額 5 選記盤點盤虧。

**Then** A 待出結清、B 可用 \+50、盤點 −5，淨額 45。

## **T04 \- 退貨（待入）**

**目標結果：**記錄客戶退回入倉。

**功能規則：**

> * 專屬：退入倉、品況（良 / 壞）、品項、數量、單位、異動日期；建議關聯原始出貨單號。

> * 收貨確認時良品計入可用、壞品強制手動記損耗（退貨壞品 / 報廢），未補記前不得結案。

**驗收標準（AC \- 含壞品退貨）：**

**Given** 客戶退回 X 10 個，其中 2 壞。

**When** 收貨確認、將 2 壞品記損耗。

**Then** 退入倉可用 \+10、損耗 −2，淨增 8。

## **T05 \- 損耗**

**目標結果：**記錄庫存單向減少（報廢 / 破損 / 遺失）。

**功能規則：**

> * 方向固定為減；必要：倉庫、品項、數量、原因類別（報廢 / 破損 / 遺失 / 退貨壞品 / 運送遺失 / 其他）、說明。

> * 不可預約：異動日期僅可填今日（含）以前（即時或補登）；損耗為已發生之事實而非計畫性動作，遇未來日期應阻擋並提示。

> * 來源：一般手動建立，或差異流程中強制手動補記（後者恆為即時、於確認步驟原子寫入）。

> * 一般手動損耗為敏感操作、需權限；差異流程之補記允許確認者當下記錄（標記來源、供複核）。

**驗收標準（AC \- 報廢）：**

**Given** A 倉 X 破損 3。

**When** 具權限者建損耗、破損、3。

**Then** A 倉 X 可用 −3。

**驗收標準（AC \- 禁止預約）：**

**Given** 使用者於損耗單填入未來日期。

**When** 送出。

**Then** 系統阻擋並提示損耗不可預約，僅能填今日（含）以前。

## **T06 \- 盤點調整**

**目標結果：**帳實校正之雙向調整（盤盈 / 盤虧）。

**功能規則：**

> * 方向可增可減；用途：定期盤點校正、及差異流程中以盤點沖平之差額。

> * 不可預約：異動日期僅可填今日（含）以前。盤點差額須實際清點後方能得知，無法預先開單；且盤點基準為現有在倉（可用＋待出），若其自身可產生待出將形成自我參照。

> * 盤點盤的是現有在倉（可用＋待出，實體仍在），不含待入。

> * 本期支援逐筆手動建立；盤點批次作業詳附錄 B。為敏感操作、需權限。

**驗收標準（AC \- 盤盈）：**

**Given** 盤點發現 A 倉 X 實際比帳多 3。

**When** 建盤點調整、盤盈、3。

**Then** A 倉 X 可用 \+3。

**驗收標準（AC \- 禁止預約）：**

**Given** 使用者於盤點單填入未來日期。

**When** 送出。

**Then** 系統阻擋並提示盤點不可預約。

## **T07 \- 生產單**

**目標結果：**引用配方消耗投入品項、產出成品；原子異動。

**功能規則：**

> * 指定成品、倉庫、數量、異動日期；引用配方以每單位用量 × 生產數量展開。

> * 預約：開單即將所需投入品項自可用移入待出（產出之成品不預先佔位）；即時：確認即扣料、成品入可用。

> * 投入若本身另有配方（半成品或組件成品），直接扣該品項庫存、不逐層展開；任一投入不足即阻擋、不得部分執行。

> * 確認時可回報實際耗料與產出；與配方展開量有差異者強制手動補記（損耗或盤點）。

> * 對配方做快照、歷史不受變更影響；落帳為多筆投入加一筆產出、綁同一單號。

**驗收標準（AC \- 依配方生產）：**

**Given** 面膜禮盒配方每盒精華液 2、單片面膜 5、包材 1；庫存充足。

**When** 生產 10 盒並確認。

**Then** 原子扣精華液 20、單片面膜 50、包材 10，產出 10 盒。

**驗收標準（AC \- 製程損耗）：**

**Given** 生產 10 盒多耗精華液 2。

**When** 確認時回報並記損耗 2。

**Then** 同單完成生產、另記損耗 −2。

## **A01 \- 自然語言異動解析**

**目標結果：**解析聊天室指令（含單位、異動日期），覆述確認後執行。

**功能規則：**

> * AI 僅解析與抽取欄位，不直接寫入；覆述顯示換算後最小單位與模式判斷（即時 / 預約 / 補登）。

> * 未帶單位或日期不明時追問；信心不足或缺欄位時要求補充或轉人工。

**驗收標準（AC \- 覆述確認）：**

**Given** 輸入「A 倉明天出貨精華液 5 盒」。

**When** AI 覆述「A 倉 出貨 精華液 5 盒（=50 個）· 預約（明日）」。

**Then** 確認後建立預約單、可用移入待出 50 個。

## **A02 \- 單據 / 影像 OCR 辨識**

**目標結果：**辨識上傳單據 / 影像，覆述（可修正）確認後執行。

**功能規則：**

> * 辨識品項、數量、單位、倉別等；覆述階段允許編輯修正。

> * 確認前不得落帳；辨識失敗或缺欄位時提示重試或改手動。

**驗收標準（AC \- OCR 修正）：**

**Given** 數量被辨識為 5O。

**When** 系統覆述。

**Then** 使用者修正為 50 並確認後才建立紀錄。

## **A03 \- AI 人設調撥規則**

**目標結果：**於人設設定倉庫間自動調撥規則；只判斷與提議，執行由程式完成。

**功能規則：**

> * 可設如『B 倉某品項低於警示值自 A 補足』；規則觸發產生調撥提議，仍須電子確認與 T03 流程。

> * 僅在發起者同時具來源倉與目標倉操作權時生效。

**驗收標準（AC \- 規則觸發）：**

**Given** 設 B 倉 X 低於 20 自 A 補。

**When** B 倉 X 可用降至 18。

**Then** AI 產生 A→B 調撥提議；確認後依 T03 建立。

# **7\. 異常處理與邊界條件（Edge Cases）**

> 1. **模式判斷界線：**異動日期今日（含）以前＝即時 / 補登（建立即落帳）；明日（含）起＝預約（需人工確認）。今日歸即時，無空隙。

> 2. **損耗 / 盤點不可預約：**T05 損耗與 T06 盤點調整僅可填今日（含）以前之異動日期，遇未來日期阻擋並提示；此二類不進待入 / 待出。

> 3. **差異補記恆為即時：**由收貨或生產確認觸發之強制手動補記（損耗 / 盤點），於該確認步驟原子寫入，不受母單原為預約或即時之影響。

> 4. **預約人工確認：**預約單須由操作者於實際執行時人工確認才落帳；異動日期到僅提醒、系統不自動確認、不自動釋放待出 / 待入。

> 5. **補登雙時間軸：**補登記異動日期（事情發生日）＋完成時間（建檔當下）；餘額一律以完成時間為準、即時生效、不回溯歷史；補登完成時間當下即填、不留空、不進待入 / 待出。

> 6. **補登不可成負：**補登不得使該倉當前『可用數』為負；違反時阻擋並提示。

> 7. **庫存足量以可用為準：**出貨 / 生產 / 調出之足量檢查一律看『可用數』（不含待出、待入），避免動用已被鎖定或未到之貨。

> 8. **待出開單即扣可用：**出貨 / 生產 / 調出之預約，於開單當下即將數量自可用移入待出（非等確認才扣），以防超領同一批貨。

> 9. **待入不扣可用：**進貨 / 調入 / 退貨之待入於開單當下不扣可用（貨尚未到），收貨確認後才計入可用。

> 10. **異動中不得淨值化：**同一（倉庫，品項）可同時有待入與待出，顯示與彙總皆須分列兩個方向，不得相互抵銷；否則調撥（A 待出、B 待入）將於彙總後歸零而消失於畫面。

> 11. **取消 / 修改預約：**取消預約：待出退回可用、待入清除；修改數量同步調整待出 / 待入，且不得超過當下可用。

> 12. **收貨差異強制手動：**入庫收貨與單據不符時，系統擋住並要求同一確認步驟原子補記差額方能結案；短少可選損耗或盤點盤虧、溢收僅能盤點盤盈。

> 13. **生產差異：**生產確認時實際耗料多於配方、或產出少於計劃者，差額強制手動補記（損耗或盤點）。

> 14. **調撥差額歸屬：**調撥短收預設記於收貨端（B）為損耗 / 盤點；查明為 A 未發出時，由管理者調整回 A。補記紀錄須標示來源單號供複核。

> 15. **開單雙入口一致性：**新增異動可於 AI 聊天室或庫存模組異動紀錄發起；兩入口須套用相同之欄位驗證、單位換算、異動日期模式、覆述確認與差異強制手動，並呼叫同一落帳程式；開單與確認皆需具該倉操作權。

> 16. **自訂欄位三種規則：**主檔＝可建新欄位（資料存主檔）；庫存列表＝欄位顯示挑選（自主檔既有欄位挑選顯示，主檔刪欄位須連動）；異動紀錄＝依單據類型設定（同類型共用一組、非每筆自由加）。

> 17. **生產成品不預佔：**生產預約僅將投入品項記待出，產出成品不預先佔位，確認完成才計入可用。

> 18. **調撥一單兩筆：**一張調撥單同時產生 A 端待出與 B 端待入兩筆不可用紀錄，類型不同。

> 19. **逾期未確認進風險：**過異動日期仍未確認之待入 / 待出，列入待處理風險並逾時提醒；差額未結清不得關單。

> 20. **滯銷判準：**滯銷＝逾該品項『滯銷天數』無出庫類異動（出貨、被生產耗用）；進貨 / 調入不重置滯銷計時。

> 21. **供需預測範圍：**預測僅計已知事件（現有可用、待入、待出 / 生產排程），不含歷史消耗外推。

> 22. **配方循環參照 / 單階：**建立 / 編輯配方禁止循環參照（組合 / 套組情境風險較高）；本期單階，投入若另有配方時直接扣該品項庫存、不逐層展開。

> 23. **配方變更不溯及：**生產單於建立當下快照配方，日後修改配方不影響既有生產單。

> 24. **最小單位與換算：**一律以最小單位記帳；可換算單位須為整數倍、一經使用即鎖定；已有交易之品項最小單位不可變更。

> 25. **開單須指定單位：**異動指令 / 表單須指定並確認單位；未帶單位者追問，覆述顯示『輸入單位（=最小單位）』對照。

> 26. **提權防護：**『設定權限』能力僅管理員；不具者不得進入設定 · 權限。

> 27. **部門與個人權限合成：**有效能力＝部門 ∪ 個人（取聯集）；任一來源變更即時生效。個人否決機制詳附錄 B。

> 28. **多聊天室範圍聯集：**使用者屬多個聊天室時，可見 / 可操作範圍為各聊天室綁定倉庫之聯集。

> 29. **主檔刪除 / 停用：**有庫存或未結交易之品項 / 倉庫 / 供應商不可刪除，僅可停用。

> 30. **主檔批量匯入驗證：**逐列驗證（必填、型別、唯一鍵、可存入品項、單位換算整數倍等），失敗列逐筆回報、不寫入。

> 31. **數量防呆：**異動數量須為正；增減方向由異動類型或調整方向決定。

# **附錄 B. 待擴充功能項目**

下列項目經評估後未列入本期範圍，於此記錄其觸發時機與對現有設計之影響，供後續版本規劃與工程預留接口之依據。

| 項目 | 觸發時機 | 對現有設計之影響 |
| :---- | :---- | :---- |
| 存貨計價與單位成本 | 需產出存貨價值、銷貨成本（COGS），或銜接財務 / 成本模組時。 | 進貨單增列「單位成本」欄位；出庫類異動需依計價方法（移動加權平均 / FIFO / 標準成本）帶出成本；新增計價方法設定。BOM 可作為標準成本之骨架。建議工程於進貨單先預留欄位，避免日後回溯補資料。 |
| 批號 / 效期追蹤 | 客戶屬食品、美妝等受效期管理或召回規範之產業時。 | 庫存維度由（倉庫 × 品項）增為（倉庫 × 品項 × 批號）；所有異動需帶批號；可支援先到期先出（FEFO）與召回追溯。影響範圍最廣，宜於導入前評估。 |
| 盤點批次作業 | 需定期實地盤點或循環盤點時。 | 新增盤點批次單頭與明細（整倉逐項輸入實際數、系統產生差異），落帳沿用既有 T06 盤點調整，不需新增異動類型。 |
| 多階 BOM 展開 | 需將半成品逐層展開至底層原料時。 | 配方展開演算法由單階改為遞迴展開，循環參照檢查需涵蓋多層；生產單快照結構須能容納層級。 |
| 生產管理模組獨立 | 需管理工單排程、工序（Routing）、機台產能、在製品（WIP）或人工成本時。 | 生產由庫存模組抽出為獨立模組，庫存僅保留「生產造成之庫存異動」；BOM 維持為跨模組共用主檔。 |
| 虛擬組合商品（Kit） | 線上販售組合 / 套組但不預先包裝、出貨當下才組合時。 | 出貨時依配方展開扣各組件，組合品本身不計庫存；與現行「先生產、組合品有獨立庫存」為兩種並存模式。 |
| 庫存分析指標 | 交易資料累積足夠、需經營分析時。 | 於 V03 分析區新增庫存週轉率 / 週轉天數（期間出庫量 ÷ 平均庫存，排除調撥）、ABC 分類、庫齡分析；純統計，不影響交易資料結構。 |
| 個人否決（deny）權限 | 需於部門已授權之情況下，單獨排除特定人員時。 | 權限合成由「部門 ∪ 個人」改為「（部門 ∪ 個人）− 否決」；A.9 權限指派需增列否決類型。 |
| 儲位（Bin）／序號追蹤／品檢凍結 | 大型倉儲需管理倉內儲位、單品序號管理、或收貨後待驗與不良凍結流程時。 | 庫存維度再增儲位層；序號為逐件追蹤；凍結為獨立於待入 / 待出之第三種不可用狀態（語意較「待出」更貼近隔離用途，如計畫性報廢之預先鎖定）。 |
| 採購與銷售模組銜接 | 開發採購 / 銷售模組時。 | 採購單（PO）與進貨單為兩張連動單據：PO 核准產生待入、進貨單引用 PO 並比對其數量（即現行「單據數量」之來源），收貨完成回寫 PO 狀態並觸發應付。銷售訂單（SO）與出貨單同理：SO 確認產生待出、出貨引用 SO 並觸發應收。現有待入 / 待出桶與差異機制可直接承接，無須改動。 |
