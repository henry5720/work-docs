# SPC 權限與部門可見範圍（現況說明）

> **對象**：PM／專案管理者
> **目的**：說明目前線上 SPC 的權限規則——誰能看什麼、誰能改什麼、部門如何限制範圍
> **對應版本**：spc-backend `1.0.4`（commit `183f69c`，2026-07-20）
> **撰寫日期**：2026-07-27
> 本文描述**目前實際行為**。文末「已知落差」列出正在調整中的項目。

---

## 一句話總結

SPC 權限由兩件事決定：**你在 TeamSync 的職級**（決定能不能管理權限、能不能跨部門看資料）＋ **你被指派的 SPC 角色**（決定能不能編輯）。資料的可見範圍另外受**部門**限制。

---

## 1. 三個名詞

| 名詞 | 是什麼 | 從哪裡來 | 誰能改 |
| :--- | :--- | :--- | :--- |
| **TeamSync 職級** | 公司組織架構裡的位階（一般員工～高階管理者） | 公司人員設定，SPC 只是讀取 | 公司管理員 |
| **SPC 角色** | SPC 模組專屬的四種角色 | SPC 的「權限管理」彈窗指派 | 中階管理者以上 |
| **部門** | 使用者所屬部門 | 公司組織架構，SPC 只是讀取 | 公司管理員 |

三者互相獨立。職級高不代表 SPC 角色高，SPC 角色高也不代表能跨部門。

---

## 2. TeamSync 職級在 SPC 的效果

| 職級 | 代號 | 可指派他人 SPC 角色 | 可跨部門檢視 |
| :--- | :---: | :---: | :---: |
| 一般員工 | 0 | ✗ | ✗ |
| 資深員工 | 1 | ✗ | ✗ |
| 初階管理者 | 2 | ✗ | ✗ |
| 中階管理者 | 3 | ✓ | ✗ |
| 高階管理者 | 4 | ✓ | ✓ |

> **注意**：高階管理者（職級 4）在 TeamSync 是**每間公司唯一的負責人帳號**。所以目前「跨部門檢視」實際上全公司只有一個人有。這一點正在調整，見文末「已知落差」。

職級**不影響**能不能編輯 SPC 資料——那是 SPC 角色決定的。一個高階管理者若沒有被指派 SPC 角色，一樣只能檢視。

---

## 3. SPC 四個角色能做什麼

| 動作 | 系統管理員<br>system_admin | 品保人員<br>quality_staff | 產線人員<br>line_operator | 檢視者<br>viewer（預設） |
| :--- | :---: | :---: | :---: | :---: |
| 檢視資料、圖表、警報 | ✓ | ✓ | ✓ | ✓ |
| 匯出 | ✓ | ✓ | ✓ | ✓ |
| 新增／編輯 管制計畫 | ✓ | ✓ | ✓ | ✗ |
| 新增／編輯 量測項目 | ✓ | ✓ | ✓ | ✗ |
| 新增／編輯 樣本資料 | ✓ | ✓ | ✓ | ✗ |
| 圖表設定、抽樣設定、警報設定 | ✓ | ✓ | ✓ | ✗ |
| 檔案匯入 | ✓ | ✓ | ✓ | ✗ |
| 使用匯入樣板 | ✓ | ✓ | ✓ | ✗ |
| **管理**匯入樣板（建立／修改／刪除） | ✓ | ✓ | ✗ | ✗ |

**幾個要點：**

- 沒有被指派角色的人一律是「檢視者」。畫面右上角會出現提示 icon，說明如何取得操作權限。
- 目前 `system_admin` 與 `quality_staff` 的能力**完全相同**，程式碼刻意分成兩個角色，是為了未來要拉開差異時不用改結構。
- `line_operator` 與前兩者的唯一差別是**不能管理匯入樣板**（可以使用，不能建立或修改）。
- 「檢視者」也能匯出。匯出不受角色限制，只受部門範圍限制。

---

## 4. 部門如何限制資料範圍

**讀與寫是兩套規則，這是最容易誤解的地方。**

| 使用者 | 看得到 | 改得動 |
| :--- | :--- | :--- |
| 高階管理者（職級 4） | **全公司**所有部門 | **只有自己部門** |
| 其他所有職級 | 只有自己部門 | 只有自己部門 |
| 沒有設定部門的人 | 只有「無部門」的資料 | 只有「無部門」的資料 |

**跨部門是唯讀的。** 高階管理者能看別部門的管制計畫、圖表、樣本，也能匯出，但**不能編輯或刪除**別部門的任何東西。嘗試編輯會得到「找不到資料」的錯誤（系統刻意不透露該筆資料存在於其他部門）。

**部門歸屬是自動的。** 資料建立時自動歸到建立者的部門，使用者不能自行選擇要建在哪個部門。透過批量匯入建立的資料也一樣。

**「無部門」是獨立的一群。** 帳號沒有設定部門的人，只看得到同樣沒有部門歸屬的資料，看不到任何有部門的資料。SPC 部門功能上線前建立的舊資料都屬於「無部門」——這些舊資料現在只有無部門的人和高階管理者看得到。

---

## 5. 哪些資料分部門、哪些是全公司共用

| 資料類型 | 是否分部門 |
| :--- | :---: |
| 管制計畫（CCM） | ✓ 分部門 |
| 量測項目（Entity） | ✓ 分部門 |
| 樣本資料 | ✓ 分部門（跟隨所屬量測項目） |
| 圖表設定、抽樣設定、警報設定、Nelson 規則 | ✓ 分部門（跟隨所屬管制計畫） |
| 產品、站別、規格標準、量測單位、等級標籤（字典類） | ✗ 全公司共用 |
| 匯入樣板 | ✗ 全公司共用 |
| 版面配置、群組設定 | ✗ 全公司共用 |

字典類與匯入樣板是全公司共用的：同公司任何人都看得到，也能編輯（只要有 SPC 編輯角色）。**部門不會擋字典。** 這代表 A 部門的品保人員可以修改 B 部門在用的規格標準。

不同公司之間永遠完全隔離，任何職級都不例外。

## 6. 常見情境

| 情境 | 結果 |
| :--- | :--- |
| 新人第一次進 SPC | 檢視者，只能看自己部門的資料，看不到任何編輯按鈕 |
| 品保人員想看隔壁部門的管制圖 | 看不到。品保角色不改變部門範圍 |
| 高階管理者想改別部門的管制計畫 | 看得到但改不動，會顯示找不到資料 |
| 中階管理者第一次進 SPC | 也是檢視者。他有權指派角色，但要先自己發一個角色給自己 |
| 產線人員想建立新的匯入樣板 | 不行，只能使用現有樣板。需請品保人員或系統管理員建立 |
| A 部門的人修改了共用的規格標準 | 會影響 B 部門。字典類不分部門 |
| 帳號沒設部門的人匯入資料 | 資料歸到「無部門」，同部門的同事若有設部門就看不到 |

## 7. 已知落差（正在處理）

| # | 問題 | 現況 | 期望 | 追蹤 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | 跨部門檢視門檻過高 | 只有職級 4（每間公司唯一的負責人帳號）能跨部門看 | 對齊平台慣例：職級 3 以上都能跨部門唯讀 | spc-backend #28 |
| 2 | 管理者要自己發權限給自己 | 職級 3／4 第一次進 SPC 也是檢視者 | 職級 3 以上未被指派時，預設為 SPC 系統管理員 | spc-backend #29 |
| 3 | 看不出目前的資料範圍 | 介面沒有任何「你正在看全公司／只看自己部門」的標示 | 跨部門檢視者要能一眼看出範圍 | 前端，未開單 |
| 4 | 權限清單不完整 | 權限管理彈窗只列出被明確指派過的人 | 落差 2 修好後，隱含權限的管理者也要顯示，否則會誤以為沒給權 | 前端，未開單 |

落差 1 的說明：目前的 `職級 == 4` 是刻意實作的（程式碼有對應測試），不是 bug。但 TeamSync 平台其他模組的跨部門判斷一律用「職級 3 以上」，職級 4 保留給不可逆的維運操作（例如資產庫的連鎖刪除）。唯讀的跨部門檢視不屬於那一類，所以建議對齊職級 3。

落差 1 與落差 2 是**兩件獨立的事**：拿到 SPC 系統管理員角色不等於能跨部門，反之亦然。
