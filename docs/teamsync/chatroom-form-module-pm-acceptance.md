# 聊天室表單模組調整 — PM 驗收說明

- 分支：`feat/chatroom-form-module-adjustment`
- 範圍：86 個 commit，2026-06-09 ~ 2026-07-27
- 影響模組：聊天室 > 表單（智慧資料表）
- 前後端關係：本次幾乎全為**前端**改動；有 2 項需等後端（見「已知限制」）

---

## 一、整體做了什麼（一句話版）

把聊天室表單模組從「舊版分散 UI + 幾個功能壞掉」整理成：
**統一的建立流程 + 統一的設定 Modal + 可自訂的分析圖表頁**，
並把前端權限判斷校正成與後端一致（原本會出現「按了才 403」的按鈕）。

---

## 二、功能區塊與驗收點

### A. 建立表單流程（CreateFormModal）

| 項目 | 說明 |
|---|---|
| 建立方式選擇 | 範本 / 匯入檔案（Excel、CSV） |
| 匯入結果卡 | 匯入後，範本清單換成「匯入來源卡」（檔名 + 解析到的欄位數），可清除並回到選範本 |
| 步驟 4 排程通知 | 建立表單時可一併設定廣播（可跳過）；驗證失敗會明確報錯，不再默默吞掉 |
| 欄位預設值 | 選範本後不再被清空（原本 merge 寫錯變成整包覆蓋） |
| 欄位展開狀態 | 刪除/重排欄位後，展開狀態跟著「該欄位」而不是「位置」 |

**驗收點**：匯入 Excel 後回頭改選範本、範本欄位帶預設值、建立時同時設定廣播。

---

### B. 表單設定 Modal（FormSettingsModal）

四個頁籤統一在一個 Modal 內：**基本資料 / 欄位管理 / 權限 / 通知**。

**基本資料**
- 名稱、描述目前為**唯讀**（後端尚無更新端點，見已知限制）
- 刪除表單走統一的確認 Modal

**欄位管理**
- 既有欄位鎖定格式（型別不可改），新增欄位可選
- 欄位名稱必填、紅色星號標示；不合法時 Save 停用
- `max_length`（字數上限）輸入框**已修復**：原本 JS→TS 改寫時掉了，導致只改字數上限完全不會送 API
- 只調整欄位順序也會顯示 loading 與成功提示（原本毫無回饋）
- 移除多餘的「拖到此處刪除」區（每個欄位本身就有刪除鍵）
- Modal 改固定高度、單一內部滾動，新增鍵固定可見，切頁籤高度不再跳動

**權限**
- 唯讀使用者看不到成員搜尋工具列（原本可以動清單並讓 Save 亮起來，是個安全漏洞）
- 移除成員時有 toast、加部門成功有 toast
- 沒有變更時 Save 停用

**通知（廣播）**
- 每月排程可正確存取（原本 monthly 分支缺 `day_of_month`，來回轉換會掉資料）
- `target_channels`（推送渠道）改為必填並驗證
- **發送紀錄（查看發送紀錄）已恢復**：JS→TS 改寫時整個掉了，現在是嵌套 Modal，接真實 logs 端點，可依狀態 / 平台 / 週期篩選
- 廣播依狀態鎖定編輯：`進行中/暫停中` 可編輯；`已完成/已取消` 唯讀（只能看指標、看紀錄、刪除）。唯讀的卡片不會被批次存檔誤觸更新
- 卡片預設收合成摘要，點開才展開編輯；共用底部批次存檔

**驗收點**：欄位只改字數上限要能存成功、唯讀成員不能編權限、每月排程存後重開值仍正確、已完成的廣播不能編輯。

### C. 記錄表格與工具列（FormsInterface）

| 項目 | 說明 |
|---|---|
| 進階搜尋 | 多條件篩選修正；日期/時間/布林選了立即套用（原本讀到舊值）；已套用條件標籤自動換行 |
| 篩選欄位 | 排除 link / formula 欄位（後端對這兩種不回傳資料） |
| 篩選可見性 | 進階篩選按鈕上有 ScBadge 顯示條件數；有套用時出現「清除全部篩選」一鍵鍵 |
| 清除搜尋 | 會一併重設分頁，表格真的會重抓（原本清了還顯示舊篩選結果） |
| Tooltip | 純圖示按鈕（進階篩選、清除、欄位顯示、設定、統計）都補上說明 |
| 分頁 | 改用 ScTable 內建分頁；小螢幕自動堆疊、縮小控制項 |
| 新增記錄 | 按鈕移進 ScTable footer 插槽 |
| 匯出 | ExportRecordModal 改用共用的篩選組裝函式，避免與進階搜尋邏輯漂移 |
| 匯入 | 三步驟（上傳 / 對應 / 預覽）流程完成 |

**驗收點**：多條件篩選、清除篩選後資料回復、手機/窄視窗看分頁。

### D. 分析圖表頁（統計，原「統計分析」）

這是最近兩週的重點，對齊 prototype。

**名詞與框架**
- 全頁統一叫「**分析圖表**」（原本混用 項目 / 模板 / 配置）
- 日期快選：全部時間 / 近7天 / 近30天 / 本月 / 上月（全域套用）
- 日期範圍改由**後端**依 `created_at` 篩選（原本前端算）
- 清除日期範圍會正確重抓（antd v6 清除回傳 `[null, null]`，已正規化）
- 頁首有「N 張分析圖表 · 日期範圍」摘要行

**卡片列表**
- 「新增分析圖表」+ 搜尋移到頁首；新增是唯一入口，搜尋只在有圖表時出現
- 搜尋可依圖表名稱 / 圖表類型即時篩選（前端）
- 空狀態引導按頁首新增；無搜尋結果狀態有「清除搜尋」
- 卡片頭：拖曳把手 + 標題描述 + `⋯` 選單（編輯 / 複製 / 刪除，含圖示），刪除仍兩段確認
- 卡片外觀：邊框 + 陰影、頭/身/尾分區留白、footer 分隔線滿版

**新能力**
| 能力 | 行為 |
|---|---|
| 置頂（pin） | 置頂的浮到最前，未置頂維持手動拖曳順序；拖曳與置頂可共存 |
| 複製 | `⋯` > 複製，產生新 id、名稱加「(複本)」 |
| 卡片頁尾 | 左：篩選條件摘要（無條件顯示「無額外篩選條件」）；右：相對更新時間 |
| 更新時間 | 只在**內容**有改時更新（新增/編輯/複製）；純置頂/排序不算改內容 |
| 卡片尺寸 | 每張卡可選 full / half / third 寬度（12 欄 grid）。KPI 數字卡可窄、寬表格可寬 |

- 尺寸只影響**寬度**：圖表內容不變、高度依內容、與置頂/排序互不干擾；小螢幕自動降級
- 舊資料相容：舊卡片視為未置頂、預設 half、不顯示更新時間，**不需資料遷移、不回寫**

**驗收點**：置頂後重新整理仍置頂、複製出的圖表可獨立編輯、改尺寸能存成功、舊有圖表照樣顯示。

### E. 權限判斷對齊後端（3 份 ADR）

原本前端與後端規則不一致，使用者會看到「按下去就 403」或「該看到卻被隱藏」的按鈕。

| 問題 | 修正 |
|---|---|
| 建立表單 / 設定按鈕 | 原本用「聊天室管理員」判斷，但後端從不給聊天室管理員表單權限。改為 `chatroom.table.manage`（建立者 OR 公司管理員 role>=3 OR 同部門部門管理員 role>=2），與後端 guard 一致。**副作用：部門/公司管理員原本被錯誤隱藏，現在看得到** |
| 編輯表單權限 | 原本任何拿到完整授權的普通成員都看到可編輯 UI，但存檔必 403。改為只有 房間擁有者 / 管理員（對齊後端 `is_table_manager`） |

**驗收點（重要，行為有變）**：
- 部門管理員 / 公司管理員 → 現在**看得到**建立表單與設定
- 純聊天室管理員（非建立者、非部門/公司管理員）→ 現在**看不到**（原本看得到但按了會失敗）
- 有完整授權的普通成員 → 權限頁**不可編輯**（原本可編但存不了）

---

### F. 智慧資料表（custom_tables）提示

- 釐清語意：`custom_tables` 是**給後端 AI agent 用的**（AI 工具箱能不能讀表），**不影響人使用表單**
- 建立表格後，若該聊天室沒開 `custom_tables`，跳一個**非阻擋**的提示 Modal 詢問是否開啟
- 提示只在聊天室 jobs 查詢完成後才出現（否則會用空陣列覆蓋，把該房其他已開的 AI 任務清掉 — 已修）
- Modal 樣式對齊 Small Dialog 設計稿（寬 480、無標題分隔線、按鈕右對齊）

**驗收點**：建表後提示出現、按「開啟」後其他 AI 任務沒被關掉。

---

### G. 權限申請審核面板（外部客戶申請表單存取）

- 舊版有這功能，JS→TS 改寫時被移除（等於掉了一個線上功能）。已先寫 ADR 記錄，再獨立恢復
- 現況：可收合的 `PermissionRequestsPanel` + 逐列審核（同意 / 拒絕，拒絕需二次確認）+ 頁籤上有未處理紅點
- 按鈕樣式修正：拒絕=灰、確認拒絕=紅、取消=文字（原本全渲染成綠色主按鈕）

**驗收點**：有待審申請時頁籤紅點出現、同意/拒絕流程可走完。

## 三、修掉的 Bug（PM 可回歸驗證）

1. **分析圖表存檔靜默失敗** — 編輯「從未置頂過」的圖表時寫入 `pinned: undefined`，Firestore 直接拒絕，**畫面沒報錯但沒存到**；同時讓同一張卡改尺寸也失效。已在寫入邊界清掉 undefined
2. **表格底部被裁切** — 新增記錄按鈕移進 ScTable footer 後，高度計算沒算 footer，footer 與分頁被容器裁掉
3. **footer 雙圓角** — 有分頁時 footer 與分頁各自圓角
4. **欄位字數上限（max_length）存不了** — 見 B
5. **廣播每月排程掉資料** — 見 B
6. **廣播發送紀錄消失** — 見 B
7. **唯讀使用者可動權限清單** — 見 B（安全性）
8. **範本預設值被清空** — 見 A
9. **清除篩選後表格沒回復** — 見 C
10. **清除日期範圍不重抓** — 見 D
11. **智慧資料表提示會誤關其他 AI 任務** — 見 F
12. **不可點的表格顯示手指游標** — ScTable 只在有 `onRow` 時才顯示 pointer

## 五、技術面整理（不需驗收，供工程參考）

- `FormsInterface`（1.7k 行 JS）改寫為 TypeScript 並拆模組；`StatisticsChart`、`FormStatisticsView`、`StatisticsConfigModal` 也轉 TS
- 表單與廣播狀態改走 TanStack Query（`use-custom-forms` 讀走 `fetchQuery`、寫入 invalidate；新增 `useBroadcastQueries`）
- `StatisticsConfigForm` 拆成 `StatisticsConfigModal/` 目錄（用途面板、圖表類型、設定表單、預覽、共用控制項 + `useStatisticsConfig` hook）
- 移除死碼：舊統計子樹（`FormStatisticsDrawer`、statistics worker、cache manager）、`PendingRequestsTab`、`useManagerStatus`、`ChatInterface copy.js`
- 補文件：forms 模組 `CONTEXT.md` 詞彙表、README 導覽、ADR 0001~0004
- 測試：cardSize 解析、置頂/複製/footer、CardSizeField 互動、undefined 清理、broadcastModel、權限 gate 純函式、max_length 送出
