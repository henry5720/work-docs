# 和椿科技 CRM 核心流程規格

> 本文件是 UI Review Atlas 的高風險狀態補充。欄位、權限與 API 細節仍以 delivery 目錄中的結構化草案為準。

## CRM-SET-001 CRM 資料權限
> 以 TeamSync 聊天室作為 CRM 的資料權限單位，綁定後聊天室全體成員可查看並操作 CRM。

### 概覽與情境
- 使用者由「設定中心」進入。
- 畫面列出已綁定聊天室、成員數、最近更新時間與移除操作。

### 需求與規則
- CRM 日常資料權限不再拆分客戶、Lead、商機、報價或任務。
- 只有具「設定管理權限」者可新增或移除聊天室綁定。
- 權限聯集、快取與生效時間需由 RD 確認。

### 互動與狀態
- 點擊「設定聊天室」開啟 CRM-SET-005。
- 移除聊天室前顯示影響人數與確認訊息。
- 權限不足時保留唯讀列表，不顯示可寫入操作。

### 資料與系統
- 主要資料：chatRoomId、chatRoomName、memberCount、updatedAt、updatedBy。
- 後端必須再次驗證設定管理權限並記錄 audit log。

### 驗收與決策
- [ ] 綁定成功後列表立即反映。
- [ ] 被移除聊天室的使用者無法再存取 CRM API。
- 待確認：權限變更是否需要重新登入。

## CRM-SET-005 設定 CRM 聊天室
> 從可用 TeamSync 聊天室中選擇 CRM 資料權限範圍。

### 概覽與情境
- 入口為 CRM 資料權限頁的主要按鈕。
- 顯示聊天室名稱、成員數與目前綁定狀態。

### 需求與規則
- 勾選代表該聊天室全體成員具 CRM 可視＋操作權限。
- 不提供倉庫、客戶類別或功能頁細分權限。

### 互動與狀態
- 支援搜尋聊天室、全選當頁與取消。
- 儲存中按鈕 disabled；成功關閉 modal；失敗保留選擇。

### 資料與系統
- 以完整綁定清單 PUT，或以差異集合 PATCH；API 草案採 PUT。
- 送出需帶版本或 ETag，避免多人同時設定造成覆寫。

### 驗收與決策
- [ ] 已綁定狀態重新開啟後一致。
- [ ] 權限不足與版本衝突有可理解的錯誤訊息。

## CRM-LEAD-003 Excel 匯入：上傳檔案
> 業務以 xlsx、xls 或 csv 批次建立 Lead。

### 概覽與情境
- 入口為「新建 Lead → Excel 匯入」。
- 第一步只處理檔案選擇、格式與基本檢查。

### 需求與規則
- 支援 xlsx、xls、csv；檔案大小與筆數上限由後端設定回傳。
- 上傳後顯示檔名、重新上傳與移除。

### 互動與狀態
- 拖放或選擇檔案後顯示 parsing 狀態。
- 格式錯誤、空檔、欄位不足使用區塊內 error。
- 載入成功後進入 CRM-LEAD-004。

### 資料與系統
- 上傳端點回傳 importJobId、欄位、樣本列、總筆數與警告。
- 原始檔保存期限與個資處理需記錄。

### 驗收與決策
- [ ] 相同檔案可重新上傳。
- [ ] 取消後不建立 Lead。
- 待確認：單次最大筆數、檔案大小與背景匯入門檻。

## CRM-LEAD-004 Excel 匯入：欄位對應
> 使用者將 Excel 欄位對應到 CRM 標準或自訂欄位，再確認匯入。

### 概覽與情境
- 顯示來源欄位、範例資料與目標 CRM 欄位。
- 系統可提出建議對應，但使用者需確認。

### 需求與規則
- 公司或姓名至少一項；聯絡方式規則由 PM 確認。
- 重複資料預設進入「疑似重複」而非覆寫既有資料。
- 同一 CRM 欄位不可被多個來源欄位重複對應。

### 互動與狀態
- 對應錯誤定位於該列。
- 匯入可為背景任務，顯示成功、部分成功與失敗筆數。

### 資料與系統
- 送出 mapping、dedupePolicy、sourceLabel 與 importJobId。
- 每列匯入結果需保留 rowNumber 與 errorCode。

### 驗收與決策
- [ ] 必填欄位未對應時不能送出。
- [ ] 可下載失敗列與原因。
- 待確認：是否允許直接建立客戶或商機；目前只建立 Lead。

## CRM-LEAD-005 名片辨識：上傳
> 拍攝或上傳名片，交由 OCR 產生可校正欄位。

### 概覽與情境
- 支援桌面選檔與行動裝置拍照。
- 上傳後保留名片縮圖與重新上傳／移除入口。

### 需求與規則
- 支援 JPG、PNG；檔案上限與壓縮方式由 RD 確認。
- 必須告知影像用途與保存方式。

### 互動與狀態
- 顯示上傳、辨識中、逾時、失敗與重試。
- 辨識中不可重複送出。

### 資料與系統
- 上傳回傳 attachmentId；OCR 回傳欄位值、confidence 與原始文字。
- 圖片存取需使用具時效簽名 URL。

### 驗收與決策
- [ ] 失敗可更換圖片後重試。
- [ ] 返回時不遺失已上傳檔案。

## CRM-LEAD-006 名片辨識：辨識結果
> 使用者確認 OCR 帶入資料，人工修正後建立 Lead。

### 概覽與情境
- 預填公司、姓名、職稱、電話、Email、地址等欄位。
- 名片影像與表單並列或可快速展開比對。

### 需求與規則
- 低信心欄位明確標示，但不可阻止人工修正。
- 建立前執行重複檢查；不自動合併。

### 互動與狀態
- 人工修改後以輸入值為準，保留 OCR 原值供稽核。
- 重複候選以提示或抽屜呈現，不清空已填內容。

### 資料與系統
- 建立 Lead 時帶 attachmentId、ocrResultId 與 fieldOverrides。
- 記錄來源為「名片辨識」。

### 驗收與決策
- [ ] 人工覆寫後建立的值正確。
- [ ] 列表可查看原始名片縮圖。
- 待確認：名片影像保存期限與刪除權限。

## CRM-OPP-003 新增商機
> 建立商機並選擇來源，以補齊 Lead、客戶、案件報備與商機之間的 funnel 關聯。

### 概覽與情境
- 可從商機管理直接建立，也可由 Lead、客戶或案件報備建立。
- 直接建立時顯示「來源」選擇，不另設補登 Funnel 按鈕。

### 需求與規則
- 客戶類型決定大型直客、經銷商、SI 的階段集合。
- 來源關聯需雙向可追溯。
- 預計金額、預計成交日與負責業務是核心欄位。

### 互動與狀態
- 選擇客戶後載入可用流程與既有關聯資料。
- 更換客戶類型造成階段不相容時需提示重新選擇。

### 資料與系統
- 主要關聯：leadId、customerId、registrationId、ownerId、pipelineType、stageId。
- 階段與流程定義由後端回傳，不由前端硬編碼。

### 驗收與決策
- [ ] 從來源頁建立後，可由兩端互相查看。
- [ ] 不同客戶類型只出現合法階段。

## CRM-REG-001 新增案件報備
> 經銷商／SI 建立報備，依六種報備類型顯示共同與專屬欄位。

### 概覽與情境
- 表單以基本資料、客戶資訊、需求產品、規格說明與附件分區。
- 案件編號由系統儲存時產生。

### 需求與規則
- 報備類型控制動態欄位與必填規則。
- 產品支援複選，每個產品有需求數量。
- 上傳元件需支援檔名、進度、重試與移除。

### 互動與狀態
- 使用分區標題與清楚欄距；長表單保留固定 modal header／footer。
- 隱藏欄位不參與驗證；切換類型時保留或清除值需明確定義。

### 資料與系統
- 後端提供 registrationTypeSchema，前端依 schema 渲染條件欄位。
- 附件先上傳取得 attachmentId，再隨表單提交。

### 驗收與決策
- [ ] 六種類型皆可完整提交。
- [ ] 錯誤會自動捲動並聚焦第一個欄位。
- 待確認：報備審核角色、退回與改版規則。

## CRM-QTE-001 建立報價單
> 從產品主檔選取品項，關聯商機並送出簽核。

### 概覽與情境
- 顯示報價單號、填單業務、關聯商機、版本與品項明細。
- 業務預設為目前登入使用者。

### 需求與規則
- 報價單號由後端建立且不可手動修改。
- 品項只能選擇啟用中的產品主檔。
- 小計、稅額與總額由後端重新計算，前端只做即時預覽。
- 目前無草稿流程；次要按鈕為「取消」。

### 互動與狀態
- 送出時顯示 loading 並避免重複操作。
- 若觸發簽核，列表狀態改為「簽核中／待簽核」。

### 資料與系統
- 送出 quote、lineItems、opportunityId、ownerId 與 version。
- 使用 idempotency key 避免重複建立。

### 驗收與決策
- [ ] 金額與版本正確。
- [ ] 產品停用或價格更新時顯示衝突提示。
- 待確認：稅別、幣別、付款條件與有效期限的正式規則。

## CRM-QTE-002 報價簽核：可操作
> 目前使用者是當前審核節點的合法審核人，可核可或退回。

### 概覽與情境
- 顯示報價摘要、簽核節點、申請人、金額與版本。
- 操作入口只在輪到目前使用者時出現。

### 需求與規則
- 假設流程：業務主管審核 → 金額達 NT$1,000,000 或折扣超過 10% 時事業處主管加簽 → 財務覆核付款條件、幣別與毛利。
- 審核人由「審核流程設定模組」決定，CRM 不維護節點。
- 退回必填原因。

### 互動與狀態
- 核可與退回需二次確認；送出後按鈕 disabled。
- 節點已被他人處理時顯示版本衝突並刷新進度。

### 資料與系統
- 前端提交 decision、comment、approvalTaskId 與 version。
- 後端驗證審核人、節點與資料版本，並寫入 audit log。

### 驗收與決策
- [ ] 非審核人無法從 UI 或 API 核可。
- [ ] 重複送出不會產生兩筆決策。

## CRM-QTE-003 報價簽核：唯讀
> 申請人或非目前審核人查看簽核進度，但不能直接改寫狀態。

### 概覽與情境
- 顯示所有節點的待處理、已核可、已退回與略過狀態。
- 不顯示核可／退回按鈕。

### 需求與規則
- 狀態值由簽核服務回傳。
- 若使用者後續成為當前審核人，重新整理後切換為可操作狀態。

### 互動與狀態
- 節點顯示角色、審核人、時間與備註。
- 逾時、撤回與作廢狀態需保留顯示空間。

### 資料與系統
- GET approval instance，不以報價 PATCH 變更狀態。

### 驗收與決策
- [ ] 唯讀狀態無任何狀態編輯入口。
- [ ] 進度與報價列表狀態一致。
