03 · Domain & state

核心資料關聯與狀態責任

Lead、客戶、商機與案件報備並非只能單一路徑轉換。建議資料模型保留來源關聯，使各端可雙向追溯。

1
Lead／外部候選來源、聯絡資料、OCR 與匯入記錄
2
客戶與聯絡人公司主體、客戶類型與負責業務
3
商機／案件報備來源關聯、Pipeline、預估金額
4
報價／簽核／任務版本、產品、審核決策與跟進

商機大型直客／經銷商／SI 各自的 Pipeline合法階段、流失原因、客戶類型相容CRM service

04 · Permission & approval

權限與簽核責任建議

為避免前端誤判，建議將 CRM 資料權限、設定管理權限與動態簽核權限視為三個不同概念。

CRM 資料權限

已確認方向

以 TeamSync 聊天室作為權限單位。綁定後，聊天室全體成員可查看並操作 CRM；目前不拆分功能頁或資料列。

設定管理權限

已確認方向

以使用者為單位，控制誰可修改聊天室綁定、產品主檔、簽核流程選擇與自訂欄位。

動態簽核權限

請 RD 確認整合

僅由審核流程設定模組回傳的當前審核人可核可或退回；其餘使用者僅能查看進度。

安全實作提醒：前端隱藏或停用按鈕僅屬操作提示，不能作為權限控制。敬請後端對設定異動、狀態轉換與簽核 decision 重新驗證，並記錄操作者、時間、前後值與 trace ID。

06 · Quality gate

開發與驗收建議

下列內容建議作為 Definition of Done 的最低基準；更完整的逐項清單請見 acceptance checklist。

UX 狀態

Required
  • Loading、empty、error、no result
  • Permission denied、conflict、offline
  • Upload progress、retry、remove
  • Success、partial success、failed rows

可存取性

Required
  • Label 與欄位／錯誤訊息正確關聯
  • Modal focus trap、Esc 與返回焦點
  • Icon-only button 具 aria-label
  • 鍵盤可操作且不只依賴顏色

測試範圍

Required
  • 金額、狀態機、Pipeline 單元測試
  • API contract 與權限整合測試
  • 名片、匯入、報價簽核 E2E
  • 關鍵畫面視覺回歸測試
