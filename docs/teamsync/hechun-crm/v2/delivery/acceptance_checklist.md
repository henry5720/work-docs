# 和椿科技 CRM 前端驗收清單

> 狀態：Draft。Prototype 用於行為與畫面對焦；正式開發仍需串接真實資料、權限與錯誤狀態。

## 共用架構

- [ ] 拆成 AppShell、ModuleTabs、PageHeader、FilterBar、DataTable、StatusTag、Modal、Drawer、Upload、ColumnSettings 等可維護元件。
- [ ] 所有列表支援 loading、empty、error、no-result、permission-denied 與 pagination。
- [ ] 自訂欄位啟用後以水平捲動呈現，固定必要欄位與操作欄，不壓縮內容。
- [ ] URL 可保存目前模組、列表條件與詳情識別，重新整理不丟失情境。
- [ ] 所有 mutation 防重送並處理 409 版本衝突。

## Lead 與名片／Excel

- [ ] 名片上傳有格式、大小、進度、失敗、重試、移除與重新上傳。
- [ ] OCR 低信心欄位可辨識，人工覆寫後建立資料正確。
- [ ] Lead 列表可查看原始名片縮圖，下載 URL 有權限與時效。
- [ ] Excel 匯入可預覽欄位、對應、自訂欄位與失敗列。
- [ ] 重複資料不直接覆寫，需進入疑似重複處理。
- [ ] 「未指派」可由具權限者直接下拉指派，更新失敗時還原。

## 客戶、商機與案件報備

- [ ] Lead、客戶、商機、案件報備之間的來源關聯可雙向查看。
- [ ] 新建商機時選擇來源，不另設「補登 Funnel」入口。
- [ ] 大型直客、經銷商、SI 顯示各自合法階段。
- [ ] 商機移至流失時要求原因；流失分析不與日常視圖切換混在同一層級。
- [ ] 案件報備依類型顯示正確動態欄位，隱藏欄位不阻擋驗證。
- [ ] 檔案上傳支援進度、重試、移除與安全下載。

## 報價與簽核

- [ ] 報價單號由後端產生；業務預設目前登入者。
- [ ] 產品只能選用啟用中的報價產品主檔。
- [ ] 金額由後端重算，前端與後端差異時以提示要求確認。
- [ ] 無草稿流程，次要操作為取消。
- [ ] 報價狀態與簽核狀態是兩個獨立欄位與狀態機。
- [ ] 只有當前審核人可核可／退回；退回原因必填。
- [ ] 非審核人只能查看進度；前端不可直接 PATCH 簽核狀態。
- [ ] 已核准版本不可直接修改，改版需建立新版本。

## 權限與安全

- [ ] CRM 資料權限由 TeamSync 聊天室綁定決定。
- [ ] 「設定管理權限」只控制可修改聊天室綁定與 CRM 設定的人。
- [ ] 前端隱藏按鈕之外，後端對每個 API 再次驗證權限。
- [ ] 名片、附件、Email、電話等個資不寫入前端 log 或 analytics payload。
- [ ] 權限、簽核、狀態與關聯異動具有 audit log。

## 無障礙與前端品質

- [ ] 每個 input 有對應 label；錯誤透過 `aria-describedby` 關聯。
- [ ] Modal／nested modal 有 focus trap、Esc 關閉、返回焦點與正確 `aria-modal`。
- [ ] icon-only button 具有可理解的 `aria-label`。
- [ ] 所有 button 明確指定 `type="button"` 或 `type="submit"`。
- [ ] 不以顏色作為狀態唯一線索。
- [ ] 360px 寬度可完成關鍵流程；資料表允許橫向捲動。
- [ ] 單元測試涵蓋金額、階段與權限規則；E2E 涵蓋名片、商機、報價簽核與聊天室權限。
