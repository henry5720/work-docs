# AI 讀不到我的表?照這個順序查

> **對象**：RD／PM（尤其是被問「為什麼 AI 查不到我的表」的人）
> **目的**：把 grant、job、insight flip、row ACL 四個機制分清楚,並標出前端缺口
> **對應版本**：teamsync-backend `5.7.1`（`328f7817`）／teamsync-frontend（`cbd123f2`）
> **撰寫日期**：2026-08-04

---

## 一句話總結

**要開幾道關,取決於這張表是「聊天室自己的」還是「部門的」。**

| | **聊天室自己的表** | **部門的表** |
| :--- | :--- | :--- |
| **要開幾道關** | **1 道** | **3 道** |
| ① 分享給這個聊天室（grant） | 不需要（本來就是它的） | ✅ 要 |
| ② 開 job | ✅ `custom_tables` | ✅ `custom_tables_department` |
| ③ 勾選系統（Insight flip） | **完全不經過這一層** | ✅ 要（除非它沒有 tag） |
| ④ 列／欄位權限 | 照常套用 | 照常套用 + SCP |

> ⚠️ **聊天室表對 AI 是最簡單的,部門表才最麻煩。**
> 很多人（包含這份文件的前一版）會誤以為「只有部門表能被 AI 看到」—— **剛好相反**。

會誤會是因為「只有部門表能用 tag 組成系統」這句話 —— **那講的是第 ③ 層,而第 ③ 層本來就只過濾部門表。** 程式碼註解說得很明確：

```python
def _insight_allowed_table_ids(db, chatroom_id, dept_table_ids, client_explicit_ids):
    """... Narrow only: result ⊆ dept_table_ids ∪ client_explicit_ids."""
```

聊天室自有表**根本不進這個函式**。

### 四層的分工

```
① ACL / grant            能不能存取這張表           ← 安全邊界
② ChatroomJobType        agent 掛不掛載工具，以及哪個 SCOPE
③ Insight system flip    哪些已授權的「部門表」進入載入集合
④ row / column ACL + SCP 實際能讀到哪些列、哪些欄位   ← 安全邊界
```

**只有 ① 和 ④ 是安全邊界。② 和 ③ 只是「載入視野」,關掉不等於撤權** —— 有 grant 的人照樣能用 REST API 讀到資料。

## 1. 第二層：ChatroomJobType（最容易漏的一層）

> Source：`src/schemas/enums.py` `class ChatroomJobType`

聊天室有一個 `jobs` 陣列,決定 agent 掛載哪些工具組。跟 Custom Tables 相關的有 **四個**：

| Job | 掛載什麼 | 前端有選項嗎 |
| :--- | :--- | :--- |
| `custom_tables` | **聊天室自有**的表 | ✅ 有 |
| `custom_tables_department` | **部門 scope** 的表（透過 chatroom grant 分享進來的） | ❌ **沒有** |
| `custom_table_commands` | 把 command 當 agent 工具 | ❌ **沒有** |
| `custom_api_tools` | 自訂 API 工具 | ✅ 有 |

實際解析 scope 的地方（`src/components/tools/custom/custom_table_tool_runtime.py`）：

```python
if str(ChatroomJobType.CUSTOM_TABLES) in jobs:
    scopes.add(CT_SCOPE_CHATROOM)          # ← 聊天室自有表
if str(ChatroomJobType.CUSTOM_TABLES_DEPARTMENT) in jobs:
    scopes.add(CT_SCOPE_DEPARTMENT)        # ← 部門表
```

兩個 job 是「**一個 toolkit 的兩個 scope**」,不是兩個 toolkit —— 一個房間可以同時開,同時開就是聯集。

> ⚠️ 一個 job 都沒開的呼叫者（legacy auto-detect 或測試直接建構）會拿到**兩個 scope**,這是刻意保留的 pre-split 行為。所以「沒開 job 卻讀得到」不一定是 bug。

後端註解把設計意圖寫得很清楚：

```python
#: The DEPARTMENT half of the custom-tables toolkit: department-scope tables
#: shared into this room by a chatroom grant. Split out from CUSTOM_TABLES so
#: a room's operator decides which SCOPE the analyst may see — the job is the
#: view, never the access (the grant + row/column ACL + the SCP floor still
#: decide every read and write, exactly as before).
#: Not mutually exclusive with CUSTOM_TABLES; a room may enable both.
```

**兩個重點**：

1. **`the job is the view, never the access`** —— job 決定「analyst 看得到哪個 scope」,不決定權限
2. **兩者不互斥** —— 一個聊天室可以同時開 `custom_tables` 和 `custom_tables_department`

### 🔴 前端缺口

兩份 job 選單**完全一樣,都只有 8 個選項**：

```
app/chat/components/chatSettings/basic/JobsSelector.jsx
app/chatV2/components/settings/basic/jobOptions.ts
    ↓ 兩邊都是
wms / dentist_booking / salon_booking / panco_booking /
ai_reasoning / custom_tables / custom_api_tools / etl_search
```

後端 `ChatroomJobType` 有 12 個。**前端少了 4 個**：
`dentist_booking_v2`、`salon_booking_v2`、**`custom_tables_department`**、**`custom_table_commands`**

**實務後果：如果你的系統放在 department scope（[03_設計時的三個決定.md](03_設計時的三個決定.md) 推薦的做法），目前沒有畫面能讓 AI 讀到它。** 只能直接打 API 設 jobs,或補這個 UI。

## 2. 「任務：智慧資料表」到底做了什麼

表格模組建完表後會跳一個 modal：

```
標題：是否要開啟 任務：智慧資料表？
內文：偵測到您尚未開啟任務：智慧資料表，開啟後即可在AI聊天室查詢內容
```
> Source：`app/chat/components/forms/EnableSmartTableModal.tsx`

按下「開啟」實際做的事：

```javascript
// app/chat/interfaces/FormsInterface.tsx:259
const handleEnableSmartTable = () => {
  const nextJobs = [...currentJobs, 'custom_tables'];
  updateChatroomJobs.mutate({ jobs: nextJobs }, { … });
};
```

**就是往 `jobs` 加一個 `'custom_tables'`。** 觸發時機是建表成功後、且 `jobs` 已載入、且目前不含 `custom_tables`（`FormsInterface.tsx:1496`）。

> ⚠️ 它加的是 `custom_tables`,**不是** `custom_tables_department`。所以這個 modal 只解決聊天室自有表。

### 名詞對齊(這三個是不同的東西)

| 名稱 | 指的是 |
| :--- | :--- |
| **表單管理** | 側邊欄的模組名稱（`locales/zh-TW/layout.json:32`） |
| **表格模組 (Chat Forms)** | 模組內部的領域名稱（`app/chat/components/forms/README.md`） |
| **任務：智慧資料表** | AI 能不能查這些表的 job 開關 |

## 3. 第三層：Insight system flip

```
GET / PUT  /private/chatrooms/setting/custom-table-tags/{chatroom_id}
```

`PUT` body 是 **完整 replace-set**：`{"tag_ids": [...]}`。

| 事實 | 影響 |
| :--- | :--- |
| system = **部門 tag** 與**已 grant 給本室的表**的交集 | 只有 department scope 有這個機制 |
| **untagged 的已授權部門表永遠載入** | 不能用「不給 tag」隱藏；要能切換必須先加入某個 tag |
| 伺服器只存 `tag_id`,每次重查 live grant + live tag | bundle 會 drift,前端不能把清單釘死 |
| 關閉 system **不是撤權** | 有 grant 的人照樣能用 API 讀 |

### 🔴 前端缺口

`listCustomTableSystemsForChatroom`（`services/teamSync/chatroomSettingsApi.js:278`）**有 service 層,但 0 個 UI consumer**。

所以就算 job 開了,「要載入哪些部門系統」仍然沒有畫面。

## 4. Agent 工具其實分兩層

> Source：`concepts/agent-toolkit.mdx`

| 主 agent 可直接呼叫 | 只有「分析子 agent」能跑 |
| :--- | :--- |
| `custom_tables_find_records`、寫入工具、指令工具、blob 工具、`custom_tables_cheat_sheet` | `query_records`、`aggregate_records`、`profile_column`、`correlation`、`join_aggregate`、`traverse_links` |

主 agent **叫不到右欄**,必須把問題委派給 `custom_tables_analyze`。

其他要知道的：

- 分析子 agent 的 prompt 開頭注入 `CURRENT DATE (UTC)`。**錨點是 UTC** —— UTC+8 使用者早上 07:00 問「今天」,解出來是前一個日曆日
- 支援滾動時間窗 `within_last` / `within_next` / `older_than`（正整數天數,或 `{"amount":N,"unit":"days"|"hours"}`）
- 計算欄位可過濾與排序,但**上限 50,000 筆存活資料**

### Command 也是 agent 工具

`agent_enabled` **預設 `true`**。存檔後 command 就出現在 agent 工具清單,`description`（≤1024 字元）就是 tool description。

**但要記得掛 `custom_table_commands` job** —— 而那個 job 前端沒有選項。

## 5. 診斷流程：「AI 說查不到我的資料」

照順序排查,不要跳。

> 💡 **聊天室自有表只需要看 1、2、5、7、8。** 第 3、4、6 步是部門表專屬 —— 如果你查的是聊天室表卻在那幾步打轉,方向就錯了。

```
1. 這張表是哪個 scope?
   └─ chatroom → 需要 job `custom_tables`
   └─ department → 需要 job `custom_tables_department`  ← 前端沒有選項!
   └─ company → 確認 grant

2. 聊天室 jobs 有那個值嗎?
   └─ 沒有 → 這就是原因。用 API 加,或補 UI

3. department 表:有 grant 給這個聊天室嗎?
   └─ 沒有 → 用 /department/{id}/tables/{tid}/chatroom-permissions/{cid} 給

4. department 表:它屬於某個 tag 嗎?
   └─ 有 tag 但沒 flip → 用 PUT custom-table-tags 開（沒有 UI）
   └─ untagged → 永遠載入,不是這個原因

5. 呼叫者的 row / column ACL
   └─ row filter 把資料濾掉了?
   └─ 欄位被 hidden columns 藏了?

6. SCP floor（只有 department 表會遇到）
   └─ 呼叫者的房間沒宣告 scope → 讀取回空頁（不是錯誤）
   └─ 寫入被 403 scp_scope_undeclared

7. 是不是問了主 agent 叫不到的工具?
   └─ 彙總／join／相關性 → 要委派 custom_tables_analyze

8. 時間相關的問題答錯?
   └─ CURRENT DATE 錨點是 UTC,不是使用者時區
```

## 6. 心智模型：安全 vs 視野

```
┌─────────────────────────────────────────────┐
│  安全邊界（關掉 = 真的不能存取）              │
│    ① ACL / grant                            │
│    ④ row / column ACL + SCP floor           │
└─────────────────────────────────────────────┘
┌─────────────────────────────────────────────┐
│  載入視野（關掉 ≠ 撤權，API 照樣讀得到）       │
│    ② ChatroomJobType                        │
│    ③ Insight system flip                    │
└─────────────────────────────────────────────┘
```

**永遠不要用 ② 或 ③ 當安全機制。** 想真的不讓人看到,只能動 ① 或 ④。
